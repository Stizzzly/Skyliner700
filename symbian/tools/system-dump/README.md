# SystemDump — Nokia 6600 / Symbian 7.0s

Отдельная утилита 0.1.0, UID 0x0F700663. Рекурсивно обходит доступное содержимое
Z:\, создаёт потоковый ZIP без сжатия на E:\SystemDump\ и после завершения
открывает стандартную отправку архива и отчёта по Bluetooth. Пользователь выбирает
принимающий компьютер. Приложение Skyliner700 не заменяется.

## Использование

1. Установить SystemDump.sis, открыть SystemDump в меню приложений.
2. Нужна доступная для записи MMC-карта E: со свободным местом под файлы Z: и
   небольшой запас на ZIP и отчёт. C: не используется как запасной накопитель.
3. Нажать 5 или левую софт-клавишу. На экране видны число прочитанных файлов,
   пропуски и текущий файл. Прогресс не содержит процентов: полный обход ещё идёт.
4. На Windows открыть Win+R → fsquirt → «Принимать файлы» до начала передачи.
5. По завершении утилита откроет Bluetooth-выбор получателя. Выбрать свой компьютер.
   Отправляются N6600_дата_время.zip и N6600_дата_время.log.
6. Если отправка отменена или не удалась, 7 повторяет её без нового дампа.
   ZIP и LOG остаются на карте; завершение SendUI не является подтверждением
   фактического получения файлов компьютером.

0 отменяет извлечение. Правая софт-клавиша или # закрывает утилиту. При отмене
и ошибке временные .part/.central удаляются, отчёт сохраняется. Для новой попытки
после ошибки или отмены закрыть и заново открыть SystemDump. Уже готовые архивы
не удаляются и не перезаписываются; повтор в ту же секунду может вернуть ошибку
существующего файла. Никакие системные файлы не изменяются.

## Состав и ограничения

ZIP содержит дерево Z/, включая скрытые/системные файлы, доступные через RFs,
и пустые каталоги. Пути кодируются UTF-8, даты — ZIP/DOS, данные сохраняются
без сжатия и проверяются CRC32. Чтение идёт блоками 16 КиБ; центральный каталог
ZIP хранится во временном файле, а не целиком в RAM. Короткие записи заголовков
буферизуются. Завершённый архив синхронизируется с накопителем перед Rename.
Ресурсы освобождаются при выходе, UI получает управление между блоками.

Отчёт содержит строки «код результата путь» (0 — файл успешно добавлен) и итог
files/skipped. Недоступный или недочитанный файл исключается из ZIP; локальная
запись ZIP откатывается, обход продолжается. Ошибки записи/нехватка места
останавливают весь сбор, показывают числовой код и не выдают .part за готовый ZIP.
Ограничения ZIP32: до 65535 записей, размер выходного файла менее 2 ГиБ (RFile EKA1).

Это файловый дамп доступного Z:, не сырой ROM и не снимок RAM. ROM/XIP-файлы
могут отличаться от обычных установочных E32-файлов; адресное пространство ROM,
аппаратные регистры и отсутствующие/недоступные RFs-данные так не извлекаются.
Для эмуляции железа одного архива может быть недостаточно. Диски C: и исходное
содержимое E: не обходятся: личные сообщения, контакты, настройки и пользовательские
файлы в дамп не входят. Источники утилиты и её SIS можно хранить в GitHub;
извлечённые файлы Nokia туда автоматически не отправляются.

## Проверки и сборка

Использован исходный S60 2nd Edition SDK 2.0, ARMI UREL, ARM32. Образ APP:
0 данных/BSS, один экспорт NewApplication, два файла APP/RSC в SIS.
Тот же zip_store.h проверяется host-тестом: потоковые блоки, CRC32, кириллица,
длинные имена, пустые файлы/каталоги, откат недочитанного файла, лимиты и IO errors.
Результат независимо проверяется Python zipfile с побайтовым сравнением.
Нативный аудит проверяет ARM32, отсутствие FP и глобальных конструкторов, SendUI.
Сам обход Z: и передача ZIP через Bluetooth на телефоне ещё не проверены.

Команды из каталога проекта (путь без пробелов):

```powershell
.\build-s60.ps1 -SdkRoot C:\S60SDK
python tests/verify_package.py SystemDump.sis C:\S60SDK
# Host ZIP test: MinGW g++ -std=c++98 -O2 -Isrc tests/zip_fixture.cpp -o zip-test.exe
# zip-test.exe fixture.zip
# python tests/check_zip.py fixture.zip
```
