# SystemDump 0.2.0 — прямой Bluetooth без MMC

Новая версия для Nokia 6600 / Symbian 7.0s. UID 0x0F700663 сохранён: устанавливается
поверх 0.1.0. В 0.1.0 ошибка -18 возникала из-за обязательного E: без MMC.
В 0.2.0 обращений к E: нет, полного ZIP на телефоне нет, SendUI/MTM не используются.

## Как получить файлы

1. Установить SystemDump-0.2.0.sis. Открыть SystemDump; в заголовке должно быть 0.2.0.
2. На компьютере открыть Win+R → fsquirt → «Принимать файлы».
3. На телефоне нажать 5. Утилита читает только Z:, создаёт список путей и CRC32
   блоками по 16 КиБ. На C:\SystemDump\ остаётся небольшой манифест и отчёт,
   а не копия всех файлов системы. Некоторое свободное место на C: всё же нужно.
4. После индексации автоматически откроется выбор Bluetooth-устройства.
   Выбрать принимающий компьютер. Выполняются SDP-поиск OBEX Object Push (0x1105),
   соединение RFCOMM и прямые CObexClient::Put с CObexFileObject::InitFromFileL(Z-path).
   Сам файл читается из ROM; временного вложения или полного архива на C: нет.
5. Дождаться TRANSFER COMPLETE, сохранить все принятые файлы в одну папку.
   Не завершать приём после одного манифеста: дальше передаются файлы и отчёт.
6. На ПК выполнить Python 3.9+ (обычно установлен у разработчиков):

```powershell
python restore_systemdump.py "C:\папка-с-принятыми-файлами"
```

Рядом создаётся новая папка N6600_дата_время_restored с деревом Z/ и
restore-report.json. Файлы имеют исходные имена и содержимое; CRC32 и размер
проверяются при восстановлении. Неполный или повреждённый файл не выдаётся
за восстановленный. Если манифестов несколько, выбрать один через --manifest.
--output задаёт новую выходную папку (существующая не перезаписывается).

Имена в Bluetooth: N6600_дата_время_000001.bin и т.д.; исходный путь записан
в N6600_дата_время_manifest.tsv. Это исключает коллизии одинаковых имён в разных
каталогах и ограничения OBEX/Windows на длинные пути. Удалять/переименовывать
принятые .bin до восстановления не следует. Содержимое не модифицируется.

0 отменяет, # или правая софт-клавиша закрывает. 7 повторяет передачу готового
манифеста и всех файлов без повторного подсчёта CRC (в том числе после ошибки
соединения). После отмены или ошибки самой индексации переоткрыть приложение.
Новый полный запуск получает новое имя с датой/временем; существующий манифест
в ту же секунду не перезаписывается. Статусы Sent отражают успешные ответы OBEX,
а итоговую проверку фактически сохранённых данных делает скрипт на компьютере.

Phase: 1 — выбор устройства, 2 — SDP, 3 — соединение, 4 — отправка,
5 — отключение, 6 — завершено. При ошибке сохраняется фаза, в которой она возникла.
Если приёмник разрывает сессию после каждого файла, эта реализация пакетной передачи
не сможет завершить всю отправку: потребуется совместимый OBEX-приёмник на ПК.
Совместимость многофайловой сессии с конкретным fsquirt ещё не проверена.

## Формат и границы дампа

Манифест ASCII, поля TSV: F<TAB>имя_BT<TAB>размер<TAB>CRC32_hex<TAB>путь_UTF16LE_hex.
D обозначает каталог, E — ошибку чтения источника (её код в поле размера).
Финальная строка # END позволяет отличить законченный список. Символы имён
сохраняются как UTF-16LE hex, включая кириллицу. Восстановление создаёт только Z/
и отвергает выход за пределы целевой папки. Метки времени/атрибуты не переносятся.

Источник — доступные файлы Z: через RFs, включая скрытые/системные каталоги.
Это файловое извлечение, не сырой образ ROM/RAM. ROM/XIP-файлы могут отличаться
от обычных установочных E32; для полной эмуляции железа этих данных может быть
недостаточно. C: и пользовательские файлы не обходятся. В GitHub публикуются
только наша утилита и исходники, а не извлечённые файлы Nokia.

## Проверки

S60 SDK 2.0 / ARMI UREL, ARM32, нет FP и глобальных конструкторов; нативный
импорт прямых OBEX/SDP API, отсутствие SendUI проверены. SIS APP/RSC/UID и
побайтовое соответствие SDK проверены. Host-тест восстановителя проверяет
дерево, кириллицу, пустые файлы/каталоги, CRC и небезопасные пути. Предыдущие
zip_store.h и ZIP-тесты оставлены в исходниках как код старой 0.1.0 и не участвуют
в нативной 0.2.0. OBEX, SDP, отмена и многофайловый приём на телефоне пока не проверены.

API сверены с примером btobjectexchange из установленного SDK; наш контроллер
написан отдельно, исходники и бинарники SDK не включены.

```powershell
.\build-s60.ps1 -SdkRoot C:\S60SDK
python tests/verify_package.py SystemDump.sis C:\S60SDK
python tests/check_restore.py
```
