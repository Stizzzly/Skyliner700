# KeyHookProbe 0.1.0 — Nokia 6600 / EKA1

Отдельный диагностический APP для эксперимента с `UserSvr::CaptureEventHook()`.
UID `0x0F700661`; это не новая сборка Skyliner700.
[Установщик](dist/KeyHookProbe-0.1.0.sis).

## Запуск

1. Передайте SIS на телефон, установите и откройте KeyHookProbe в меню.
2. Нажмите 5, центр джойстика или левую софт-клавишу Run.
3. Перепишите Phase, Exit type, Reason и Category с экрана результата.

Тест выполняет один CaptureEventHook и немедленный ReleaseEventHook в отдельном
рабочем потоке. Между возвратом захвата и освобождением нет файловых/оконных
операций. RequestEvent не вызывается, события не читаются и не пересылаются.
Журнал `C:\KeyHookProbe.log` дописывается с flush контрольных точек; до опасного
вызова записывается BEFORE CaptureEventHook. Паника рабочего потока может быть
показана родительским UI-потоком, если процесс и система продолжают работать.

## Результаты

| Phase | Наблюдение |
|---|---|
| 0 | До входа в тест / ошибка создания потока |
| 1 | Ещё нет отметки возврата CaptureEventHook |
| 2 | CaptureEventHook вернулся, ReleaseEventHook ещё не вернулся |
| 3 | Оба void-вызова вернулись |

Exit type: 0 = EExitKill (в том числе обычный возврат worker с reason 0),
1 = EExitTerminate, 2 = EExitPanic. Для panic важны одновременно category и reason.
CaptureEventHook имеет тип void в SDK 2.0: -14 нельзя объявлять его C++ return value.
Сообщение THREAD CREATE FAILED относится к созданию потока, не к захвату хука.

Phase 3 доказывает только возвращение обоих вызовов. Она НЕ доказывает ни
получение raw input, ни перехват владения у WSERV, ни восстановление прежнего
обработчика. Политика ядра конкретной прошивки пока не установлена.

При живом UI примерно через 5 секунд ожидания посылается Kill с KErrTimedOut;
это наш тайм-аут, не код отказа CaptureEventHook. После результата приложение
автоматически закрывается примерно через 30 секунд. Таймер не способен
восстановить зависшее ядро. Восстановление ввода WSERV после успешного захвата
не гарантировано; при нарушении ввода или зависании может потребоваться
перезапуск телефона. Освобождение вызывается рабочим потоком только после
возврата захвата; UI не пытается освобождать чужой хук вслепую.

## Сборка и проверки

Нужен тот же S60 2nd Edition SDK 2.0 и Windows Perl, что для игры.
Копируйте проект в короткий путь без пробелов (например `C:\S60\KeyHookProbe`):
старый Windows Perl не открывает очень длинные пути сгенерированных файлов.
Запустите `build-s60.ps1 -SdkRoot C:\S60SDK`.
Результат — KeyHookProbe.sis. SDK в исходники не включён.

Host-проверка `tests/probe_tests.cpp` моделирует отказ захвата/освобождения и
проверяет последовательность и фазы; это не эмуляция ядра EKA1.
`python tests/verify_package.py KeyHookProbe.sis SDK` проверяет UID,
две полезные нагрузки APP/RSC и их идентичность результатам SDK.
Нативная ARMI UREL сборка: PASS; writable data/BSS: 0; export NewApplication: 1.
На настоящем телефоне тест ещё не выполнен.
