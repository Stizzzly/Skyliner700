## Исходные заметки автора

1. Математический джекпот в ReciprocalDivide: 32-битный остаток вместо 64-битного!

Посмотри внимательно на эти три строчки в ReciprocalDivide:

C++

    unsigned q=(unsigned)((magnitude*inverse)>>40);
    UWide remainder=magnitude-(UWide)q*(unsigned)denominator;
    if(remainder>=(unsigned)denominator){++q;remainder-=(unsigned)denominator;}
    if(remainder>=(unsigned)denominator)++q;

Смотри, что тут заставляет делать тип UWide (unsigned long long) в GCC 2.9:
Компилятор делает 64-битное умножение (UWide)q * denominator, затем 64-битное вычитание с заёмом (subs + sbc), а затем два 64-битных сравнения старших и младших слов!

А теперь математический факт:
В твоём комментарии написано (и доказано), что q занижает точное частное максимум на 2.
Значит, истинный остаток R=magnitude−q⋅denominatorR=magnitude−q⋅denominator гарантированно лежит в диапазоне:
0≤R<3⋅denominator0≤R<3⋅denominator
Так как denominator — это v.z (который в тысячу раз меньше 230230), истинный остаток RR всегда помещается в обычное 32-битное беззнаковое число (unsigned)!
А раз результат вычитания гарантированно меньше 232232, то по законам модульной арифметики ( mod  232)(mod232) старшие 32 бита обязаны обнулиться, и нам вообще не нужно считать старшие 32 бита произведения!
Смотри:

C++

    unsigned denom=(unsigned)denominator;
    unsigned remainder=(unsigned)magnitude-q*denom;
    if(remainder>=denom){++q;remainder-=denom;}
    if(remainder>=denom)++q;

100% побитово тот же самый результат, но вместо 64-битной арифметики в каждом из трёх делений Project() процессор делает одну 32-битную инструкцию mul, один sub и один 32-битный cmp!
2. Схлопывание дерева ветвлений внутри скан-линии в RasterScreen

Посмотри на самый горячий внутренний цикл в RasterScreen (выполняется на каждой строке каждого треугольника для edge = 0..2):

C++

        for(int edge=0;edge<3;++edge){
            int w=row[edge],step=dx[edge];
            if(step>0&&w<0){int bound=(int)EdgeFloor((unsigned)(-(w+1)),edgeDivisor[edge],edgeInverse[edge])+1;if(bound>first)first=bound;}
            else if(step<0){if(w<0){last=-1;break;}int bound=(int)EdgeFloor((unsigned)w,edgeDivisor[edge],edgeInverse[edge]);if(bound<last)last=bound;}
            else if(step==0&&w<0){last=-1;break;}
        }

Посмотри, что происходит в самом частом случае, когда точка левого или горизонтального ребра уже внутри треугольника (w >= 0 и step >= 0):

    Проверяется step > 0 && w < 0 (2 сравнения).
    Проваливается в else if (step < 0) (ещё 1 сравнение).
    Проваливается в else if (step == 0 && w < 0) (ещё 1–2 сравнения).
    Итого 4–5 проверок впустую!

Переверни условие от знака w < 0 — тогда ветки step < 0 и step == 0 при w < 0 склеиваются в одну проверку if (step <= 0):

C++

        for(int edge=0;edge<3;++edge){
            int w=row[edge],step=dx[edge];
            if(w<0){
                if(step<=0){last=-1;break;}
                int bound=(int)EdgeFloor((unsigned)(-(w+1)),edgeDivisor[edge],edgeInverse[edge])+1;
                if(bound>first)first=bound;
            }else if(step<0){
                int bound=(int)EdgeFloor((unsigned)w,edgeDivisor[edge],edgeInverse[edge]);
                if(bound<last)last=bound;
            }
        }

Когда w >= 0 и step >= 0, процессор делает всего два cmp вместо пяти и сразу идёт дальше!
3. В Soft3D::View компонента right.y ВСЕГДА равна 0, а у сетки земли X и Z повторяются по 9 раз!

Глянь в Soft3D::Render:

C++

right=V(cy,0,sy);

У вектора right координата y всегда равна нулю! Но для каждой вершины мира (81 вершина земли + самолёт + полоса + разметка) функция View() вызывает Dot(relative, right), которая честно считает RawMul(relative.y, 0) и RawAdd(..., 0)!

Мало того — посмотри на цикл трансформации 81 вершины террейна:

C++

    for(int vertex=0;vertex<81;++vertex){
        terrainView[vertex]=View(terrain[vertex]);

В сетке 9x9:

    Вдоль каждой строки (tz = 0..8) у всех 9 вершин абсолютно одинаковый z (oz + (tz-4)*100).
    Вдоль каждого столбца (tx = 0..8) у всех 9 вершин абсолютно одинаковый x (ox + (tx-4)*100).

Посмотри на порядок операций внутри View():
Dot(rel, basis) = RawAdd(RawAdd(RawMul(rel.x, basis.x), RawMul(rel.y, basis.y)), RawMul(rel.z, basis.z))!
Так как rel.x зависит только от столбца tx (9 значений), а rel.z зависит только от строки tz (9 значений), ты можешь посчитать RawMul(rel.x, ...) 9 раз вместо 81, и RawMul(rel.z, ...) 9 раз вместо 81, а внутри цикла 9x9 считать только y (высоту) и складывать тем же самым RawAdd в том же самом порядке!
Это побитово на 100% идентично, но срезает две трети всех умножений на трансформации террейна (144 умножения вместо 729)!
4. Та же самая константа X + Y у всех 15 полосок разметки ВПП!

Посмотри на цикл разметки полосы:

C++

        for(int mark=-280;mark<300;mark+=40){
            Quad(V(-Fix::Raw(32768),Fix::Raw(5243),(Fix)mark),V(Fix::Raw(32768),Fix::Raw(5243),(Fix)mark),V(Fix::Raw(32768),Fix::Raw(5243),(Fix)mark+18),V(-Fix::Raw(32768),Fix::Raw(5243),(Fix)mark+18),RGB(240,235,205));
        }

У всех 15 полосок (60 вершин!):

    Все 30 левых вершин имеют одни и те же x = -Fix::Raw(32768) и y = Fix::Raw(5243).
    Все 30 правых вершин имеют одни и те же x = +Fix::Raw(32768) и y = Fix::Raw(5243).
    А у пар вершин (a, b) и (c, d) одинаковый z (mark и mark + 18)!

Внутри View() сумма первых двух слагаемых скалярного произведения RawAdd(RawMul(rel.x, basis.x), RawMul(rel.y, basis.y)) одинакова для всех 30 левых вершин и одинакова для всех 30 правых вершин!
Если посчитать Vec leftXY и Vec rightXY один раз перед циклом for(mark), то на каждой полоске разметки вместо 4 полных вызовов View() (36 умножений) останется всего 6 умножений (по 3 на mark и mark + 18) + сложение с leftXY/rightXY!
5. Развёртка внутреннего цикла ClearSky на 4 пары (SKY_W = 88 делится на 8!)

В ClearSky:

C++

        if(((size_t)row&3)==0){
            for(int x=0;x<SKY_W;x+=2)WritePair(row+x,packed);
        }

Так как SKY_W = 88 (а на нативном экране 176) нацело делится на 8, в цикле x += 2 процессор 44 раза на каждой строке тратит по 3–4 такта на add + cmp + blt после каждого одиночного str.
Разверни шаг до x += 8 (четыре WritePair подряд):

C++

        if(((size_t)row&3)==0){
            for(int x=0;x<SKY_W;x+=8){
                WritePair(row+x,packed);
                WritePair(row+x+2,packed);
                WritePair(row+x+4,packed);
                WritePair(row+x+6,packed);
            }
        }

Это убирает 3432 условных перехода за кадр (на 88x104) или 13 728 переходов за кадр (на 176x208)!
